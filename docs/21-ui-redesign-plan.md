# 21 — UI Redesign: Broadcast/Esports Direction

> **Status:** plan, ready to execute · **Owner:** Codex · **Supersedes:** the "premium software
> company, not a gaming website" stance in [`design-system.md`](./design-system.md) §1 for the
> **marketing** surfaces only.

## 1. Why this exists

BlitzIt is a live, weekly, spectated competition. The current marketing surface is styled like a
developer tool — restrained, light-first, Linear-adjacent — which undersells the one thing that
makes the product interesting: **an event is happening right now and you can watch it.**

The reference is [esportsworldcup.com](https://esportsworldcup.com/en): dark, broadcast-grade,
countdown-led, dense with live state.

### What "clone the style" means here — and does not

| Do | Do not |
|---|---|
| Match the **aesthetic**: dark base, bold display type, countdown-led hero, card grids, high-contrast CTAs, tight section rhythm | Copy EWC's logos, artwork, photography, copy, or licensed fonts |
| Reuse **structural patterns**: sticky nav, full-bleed hero with overlay, banded sections, 2–4 column grids | Reproduce their page as ours — no verbatim clone output shipped to `src/` |
| Keep BlitzIt's brand (`#7F5AF0`, `#00FFA3`) as the accent system | Adopt their brand colours or wordmark |

Ditto is used to **study** the reference — capture structure, spacing rhythm, type scale, motion —
into a scratch directory. Nothing generated by Ditto is copied into `src/` verbatim.

## 2. Hard constraints (do not violate)

These are the rules the last eight epics were built under. A UI redesign touches presentation
only.

1. **No server module changes.** `src/server/**` is off limits except where a page needs a *read*
   that already exists. If a new read seems necessary, stop and report it rather than adding one.
2. **All 14 verification suites must still pass**, unchanged:
   `auth, queue, runner, evaluation, evaluation:e2e, profiles, tournament, bracket, submission,
   admin, sudden-death, tournament:e2e, live-arena, spectator`.
3. **Never weaken a reveal gate or an authorization check.** In particular:
   - `listBracketRounds(..., { revealProblems: false })` on every competitor/public surface.
   - The arena stays private to the two competitors.
   - `listUserBadges(..., { publicOnly: true })` and `listPublicPlacements` on public profiles.
   - Unlisted tournaments 404 everywhere public.
4. **Server components stay server components.** `LiveRefresh` + `Countdown` are the only client
   islands the live surfaces need. Do not convert a page to a client component to animate it —
   that would duplicate the reveal rules on the client.
5. **Accessibility is not negotiable** (design-system §2):
   - `#00FFA3` **always** takes a black foreground. White on it is 1.33:1.
   - On dark backgrounds the primary lightens to `oklch(0.70 0.18 289.47)` for text.
   - Visible focus ring on every interactive element; keyboard order preserved.
   - Respect `prefers-reduced-motion` — every animation must have a no-motion path.
6. **Quality gates:** `npm run typecheck`, `npm run lint`, `npx prettier --check .`,
   `npm run build` all clean.

## 3. Phases

### Phase 0 — Reference capture (scratch only)

1. Confirm `DITTO_API_KEY` is set. **It is currently absent from `.env.local`** — if it is still
   missing, skip Ditto entirely and work from the design notes in §4, which are sufficient.
2. Clone the repo *outside* this project (e.g. `../ditto.site`), never into `src/`.
3. `npm run clone -- https://esportsworldcup.com/en --mode=multi --styling=tailwind --framework=next --out=../ditto-capture`
4. Read the capture for: type scale, section heights, grid gutters, card aspect ratios, hover
   and scroll behaviour, sticky-nav mechanics. Write findings into
   `docs/21-ui-redesign-plan.md` §4 as concrete numbers.
5. **Add `../ditto-capture` to nothing.** It is a reference artefact, not a dependency.

### Phase 1 — Tokens and theme (`src/app/globals.css`)

The single highest-leverage change. Everything else follows from it.

- **Dark-first for marketing.** The `(marketing)` group renders dark regardless of the user's
  theme; `(app)` and `(admin)` keep the existing light/dark toggle. Implement by scoping a
  `data-surface="broadcast"` attribute on the marketing layout rather than forcing `.dark`, so the
  app's theme switch is untouched.
- Add broadcast-only tokens: `--surface-deep` (near-black base), `--surface-raised` (card),
  `--surface-elevated` (hover), `--hairline` (low-contrast dividers), `--glow-primary`,
  `--glow-live`.
- Keep every existing semantic token working. **Nothing in `(app)`/`(admin)` may shift.**
- Verify the four contrast pairs in design-system §2 still hold in the new dark surfaces, and
  record the measured ratios in the doc. Do not guess them.

### Phase 2 — Primitives

Extend, do not replace. Existing call sites must keep compiling.

| Component | Change |
|---|---|
| `ui/button.tsx` | Add `broadcast` variant: uppercase, tracked, heavier weight, larger tap target |
| `ui/badge.tsx` | Add a `live` tone — `#00FFA3` on black with a pulse that respects reduced motion |
| `ui/card.tsx` | Add a `broadcast` surface variant: darker, hairline border, hover lift |
| **new** `ui/section.tsx` | Banded section wrapper — full-bleed background, contained content, consistent vertical rhythm |
| **new** `ui/display-heading.tsx` | The oversized display type the hero and section headers need |
| **new** `features/live-pill.tsx` | The "● LIVE" indicator, driven by real snapshot state |

### Phase 3 — Marketing surfaces (the visible win)

**`/` (screen [1])** — restructure into broadcast bands:
1. **Hero:** full-bleed, dark, countdown at display size (reuse `Countdown`, do not reimplement),
   tournament name, live pill when `status === 'LIVE'`, primary CTA. If a stream URL is set, the
   embed becomes the hero background/foreground rather than a boxed panel below.
2. **Live strip:** participant count · prize pool · current round · matches decided — as a tight
   horizontal band of large numerals, not four equal cards.
3. **Bracket band:** full-bleed dark, the existing `BracketTree` on a broadcast surface.
4. **Standings band:** top 10, larger rows, rank numerals emphasised.
5. **How a week works:** four steps, kept — restyled as a numbered horizontal rail.
6. **Champions band:** Hall of Fame teaser as portrait-ish cards.
7. Preserve every existing state: no tournament scheduled, registration open, live, completed.

**`/leaderboard` (screen [12])** — broadcast table: bigger rank column, city/seed as secondary
metadata, sticky header, the viewer's own row pinned and highlighted.

**`/hall-of-fame` (screen [3])** — podium-led cards; champion visually dominant.

**`/u/[username]` (screen [4])** — dark profile with badges as the visual anchor.

**New: `/rules` (screen [2])** — currently missing. Static explainer of scoring (60/15/10/15) and
the D20/D22 rule that **AI evaluation applies only from the semi-finals onward**. The landing page
already states this; give it a home.

**Marketing shell** — a real header (wordmark, Competitions / Leaderboard / Hall of Fame / Rules,
sign-in CTA) and a footer. Currently `(marketing)` has no shell at all.

### Phase 4 — Application surfaces (restrained)

The dashboard and arena stay **dense and functional** — design-system §1's Marketing ≠ Dashboard
split survives this redesign. Only two changes:

- **`/arena/knockout/[matchId]`** gets a broadcast header band: the two competitors, seeds, and
  the countdown at display size. Everything below stays as it is.
- **`/bracket/[tournamentId]`** picks up the broadcast surface tokens.

Do **not** restyle `(admin)`. It is an operator tool and was signed off in E5.

### Phase 5 — Documentation and gates

1. Rewrite `docs/design-system.md` §1 to state the **new** split honestly:
   marketing = broadcast/esports; app + admin = dense productivity tool. Leave the accessibility
   rules in §2 untouched and re-verify the numbers.
2. Update `docs/12-ui-screens.md` for every screen touched.
3. Add `CHANGELOG_UI_REDESIGN.md`: what changed, what did not, measured contrast ratios,
   before/after notes, anything deferred.
4. Run all 14 suites + all four gates. Report the matrix.
